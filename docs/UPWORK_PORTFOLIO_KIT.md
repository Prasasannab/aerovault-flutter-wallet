## 4. Technical Interview & Objection Handling Cheat Sheet

When clients interview you, be prepared to answer with confidence:

### Q1: "Why did you choose Flutter over native iOS (Swift) / Android (Kotlin) for a banking app?"
> *"Flutter compiles directly to native ARM machine code via ahead-of-time (AOT) compilation, rendering directly to Skia/Impeller. By using Flutter with Clean Architecture, we achieve 60/120fps visual fidelity and share 95% of domain logic, state management, and tests across iOS and Android while still binding directly to native platform channels for hardware-backed Secure Enclave, Android Keystore, FLAG_SECURE, and native blur filters."*

### Q2: "How do you protect API tokens and sensitive customer data on mobile devices?"
> *"We never store sensitive tokens in SharedPreferences or UserDefaults. In AeroVault, all tokens and keys are encrypted via `flutter_secure_storage` backed by the iOS Secure Enclave (`first_unlock_this_device`) and Android Keystore with AES-256 GCM. Furthermore, sensitive values in memory use ephemeral session keys that are automatically wiped if an anti-tamper trigger (root/jailbreak/debugger) is tripped."*

### Q3: "Why BLoC over Riverpod or Provider for this kind of project?"
> *"For high-ticket enterprise financial software, BLoC is the industry standard because of its strict event-driven architecture, unidirectional data flow, and predictable state transitions. Every user action is a traceable event that can be logged for compliance audits, and states are strictly immutable. Additionally, `bloc_test` provides seamless testing without needing complex mock widget trees."*

### Q4: "How do you justify an $8,000–$20,000 fixed price or $75+/hr rate?"
> *"Amateur developers write code that works on day one but accumulates technical debt, fails Apple/Google compliance reviews, or gets exploited by proxy injection. My rate reflects enterprise architecture: bank-grade security, zero technical debt, 100% test coverage, and documentation that allows any engineering team to scale the product seamlessly without costly rewrites."*
